# Bookiro Android release recovery — Pi/DeepSeek integrator prompt

You are the lead integrator for the Android release of Bookiro. Execute the work in this repository; do not merely write a plan. Use focused subagents with isolated ownership, integrate their work, test on a connected phone when available, and leave an honest handoff. The product is an ebook, audiobook and podcast app. Android ships first. Do not modify or merge the iOS port.

## Ground truth, not assumptions

On 2026-10-01, GitHub showed `trollieske/bookrio` `main` at `5e99ec2` containing overnight torrent/audiobook, playback, reader and Bookiro rebrand commits. `trollieske/shelf` `rebrand/bookiro-android` at `ca86c7e` has the rename but lacks those fixes. `bookrio/ios-parity` is independent. These remote observations are NOT proof of the local working tree or the downloaded APK. The user installed an APK downloaded manually from GitHub: its launcher still says **Bookrio**, not **Bookiro**. The user confirms the simplified reader is still broken. In Android Auto the app is selectable but opening it shows black; its media card shows the app icon and grey placeholders instead of meaningful media details. Prior commits claim fixes; device behavior disproves release readiness.

## Phase 0 — integrator: preserve and identify

- Inventory `pwd`, `git worktree list`, status/diffs, branches, remotes, ahead/behind, recent commits and tags in BOTH local repositories/worktrees. Do not reset, clean, force-push, overwrite a dirty tree, or discard unpushed audiobook work. Select the actual Android source of truth from evidence, provisionally `bookrio/main`; do not merge the older Shelf rebrand wholesale or drag Android changes into `ios-parity`. Keep Shelf available as historical backup.
- Identify the EXACT APK downloaded from GitHub and the installed package/version/build. Inspect the APK's packaged default and locale-specific labels, merged manifest, signing identity and build provenance; compare its hash/commit/artifact to the source. A source `app_name=Bookiro` does not prove the downloaded artifact or launcher label is Bookiro. Determine whether the issue is wrong/stale artifact, build variant, locale, manifest/activity alias, launcher cache, or genuinely wrong source. Do not uninstall/clear data to make the name look right.
- Establish baseline builds/tests and a short evidence log. Commit only on a dedicated Android release-recovery branch from the verified base; subagents never push or edit each other's files. Integrator alone handles shared files, manifest, Gradle, app navigation, final device install and publication.

## Delegation and integration contract

Launch independent subagents in parallel only after Phase 0. A owns branding/build-artifact provenance (`app` resources and Android build/release packaging). B owns Android EPUB reader (`reader` and its dedicated tests). C owns Android Auto Media3 browsing/session (`player` car integration, manifest changes proposed to integrator). D audits torrent/audiobook/podcast regressions and owns only focused tests or isolated fixes in `torrent`, `library`, `podcast`; coordinate any `player` edit with C through the integrator. Give each subagent its own branch/worktree or non-overlapping file ownership. Each must return reproduction, root cause, exact files, commit, tests and unresolved risks. Integrate sequentially; run build/tests after each merge. No mass cherry-pick across repositories, no speculative broad refactor, no claim that a JVM test proves a device bug.

## A — Bookiro brand and installable APK

- Make the installed Android app display **Bookiro** consistently in launcher, recent-apps, Android Auto app listing, notifications, onboarding/About and all 10 supported locales. Keep existing app data and `applicationId`/package/signing identity stable; do not create a second installed app. Do not rework logo artwork unless it visibly contains old lettering; retain its design.
- Inspect actual merged manifests, `android:label` references, aliases and per-variant resources. Build a fresh debug APK from a known commit and verify packaged labels for default + relevant locales with Android SDK tooling. Compare APK SHA-256 and source SHA; install as an update (no uninstall, no data clear) and verify launcher label on the device. Check Android Auto after reinstall/refresh too.
- If GitHub's downloadable APK comes from an old tag/branch/artifact, fix the release packaging/description so its filename, version, branch, commit and SHA-256 identify the real build. Do not present an old artifact as the new release. Do not silently publish a production release.

## B — replace the broken Android reader, not just curl

- The overnight change removed curl but STILL renders a page to a bitmap. The user tested it and says it is not fixed. Reproduce with at least two failing EPUBs if available; use a small synthetic EPUB with TOC, front matter and 3+ chapters as a regression fixture. Inspect actual rendering, pagination, chapter boundaries, preferences, controls, bookmarks, highlights/selection if supported, TTS and resume. Record specific failures before replacing the engine.
- Choose a stable direct text-rendering EPUB solution. Evaluate integrating Readium Kotlin Toolkit's EPUB Navigator first (it supports paginated reading, preferences and Locator-based positions) against the existing format and UI requirements. If unsuitable, document why and implement an equally robust direct WebView/HTML pagination approach. DO NOT make another Compose Bitmap/ImageBitmap page cache, screenshot pipeline, shader, fake overlay page or time-based patch. A simple instantaneous or subtle slide/fade navigation is enough; dependable text and progress matter more than animation. Preserve existing PDF/CBZ/non-EPUB paths unless separately proved broken.
- If migrating from chapter-local page indices, implement a defensible old-position migration to a stable locator/anchor or documented best-effort nearest text location. Do not map old page N blindly to new page N; font size and viewport change pagination. Preserve existing rows/bookmarks, support forward/back across chapter boundaries, font/theme, TOC, orientation, process death and offline operation. Reader controls must not cause unexplained reflow or black/blank pages. Remove obsolete bitmap/curl dependencies only after replacement passes tests.
- Require device tests of first page, 20+ successive turns, backward turns, both directions across chapter boundaries, TOC jump, font/theme and rotation, reopen/resume, bookmarks, and the user's problematic books. Report any unsupported legacy-format behavior explicitly. No 'fixed' claim based only on assembleDebug.

## C — Android Auto: browse AND playback

- Work only while parked or with Desktop Head Unit. Do not ask the user to test while driving. Independently test the actual exported MediaLibraryService via a MediaBrowser client: connection, `onGetLibraryRoot`, `onGetChildren` for root/book/chapter (and podcast if exposed), `onGetItem`, browsing flags, playable IDs, titles and artwork URI. Capture errors and targeted logcat. An app icon in Auto is NOT proof that the browse tree works.
- Test separately: audiobook playback begun on phone; podcast begun on phone; selection/play from Auto; transitions audiobook→podcast→audiobook; background, lock and service/process recreation. Inspect which MediaSession Auto connects to, active MediaItem, playback state, title/artwork, commands and transport controls. Locate why the card is empty and why browse opens black. Test empty library and permission failures without hanging the car UI.
- Repair the verified root cause in manifest/service/session/browse metadata or ownership. Coordinate with D to avoid two competing sessions or reintroducing stale audiobook cover on podcasts. Add service/browse tests plus a real DHU/parked-car smoke. If car hardware is unavailable, clearly separate browser-harness proof from an unverified real-car result.

## D — regression audit of the overnight fixes

- Verify the torrent fix imports only the completed torrent's verified own files and that old one-chapter imports can regain REAL chapters without destroying progress. Exercise a single-file M4B with genuine embedded markers, a chapterless file, and a multi-track folder. Never invent timed chapters.
- Verify audiobook/podcast ownership handoff, metadata, cover fallback, resume and no duplicate notification with rapid A→B→A switching. Do not reimplement either player just because two services exist. Add missing targeted tests and propose a narrow fix only if a bug is reproduced.

## Release gates and handoff

Run relevant module tests, `./gradlew :app:assembleDebug`, broader unit tests and localization validation. Distinguish pre-existing failures from introduced ones with evidence. Verify packaged APK label and install/update on the phone without wiping user data. Test reader and both audio types; test Android Auto in DHU or parked car. Do not weaken tests, assert green after a partial run, or loop endlessly on one failure. After two identical failed CI/build attempts, save the error and isolate it. Keep separate commits for branding, reader, Auto and regression fixes. Do not merge into release, rename/archive Shelf, force-push or publish an APK without explicit approval.

Final answer: a concise matrix for A/B/C/D with observed cause, commit, tests, on-device evidence and remaining failures; source and APK SHAs; Android Auto browse/session results; data-migration outcome; and exact next release action. If the reader is still bitmap-based or Auto remains black, say NOT READY rather than calling the job finished.
